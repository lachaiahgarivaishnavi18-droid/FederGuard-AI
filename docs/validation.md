# Validation record

Validated locally on 7 November 2026 using bundled Python 3.12 and Node 24 on Windows.

- Backend: **20 automated tests passed**, including SQLite foreign-key enforcement, bank-local privacy status, and public registration options without invitation-secret disclosure. Covers authentication/logout, role checks, bank invitations, tenant isolation, database persistence, upload bounds/types, evidence permissions and revocation, second-reviewer approval, prompt-like queries, graph and LangGraph output, FedAvg weights/anomalous tensors, FedProx, non-IID distributions, model optimization, dropout/quorum, model versions, minimized update envelopes, privacy composition, replay and budget exhaustion.
- Frontend: TypeScript compilation and Vite production bundle passed; four JavaScript chunks, each below the 500 kB warning threshold after splitting.
- Browser: Chromium exercised 13 authenticated routes, a cited demo answer, bank-local risk scoring, case creation and desktop/mobile layout. No page errors or horizontal overflow. Saved screenshots in `docs/screenshots` were visually inspected.
- Distributed web workflow: coordinator plus three independent bank processes completed a real round and published a model with public synthetic holdout metrics and per-client Opacus accounting metadata.
- Native Flower workflow: separate Flower server and three isolated client processes completed a round; logs are in ignored `runtime/flower-smoke-*`. This validates local compatibility transport, not cryptographic aggregation or real institutions.
- ML: `docs/reports/evaluation.json` contains measured local-only, five centralized synthetic baselines, federated and privacy-utility experiments. `shap-example.json` contains actual synthetic logistic SHAP values. Scores may be weak; no metrics are fabricated or substituted in the UI.
- RAG: `rag-evaluation.json` contains a three-query labeled synthetic benchmark. Precision@5 is 0.4, recall@5 is 1.0, MRR is 1.0, NDCG@5 is 1.0, and the insufficient-evidence check passes. This small benchmark cannot establish general retrieval or answer quality.

Not exercised: Docker image builds/Compose, PostgreSQL, TLS/mTLS, external LLM providers, downloaded neural embeddings/FAISS/cross-encoder models, cryptographic secure aggregation, production secret infrastructure, load/performance testing, independent semantic faithfulness/contradiction scoring, penetration testing and fairness studies. Dependency deprecation warnings are present for the installed Starlette/AnyIO and Flower/Typer compatibility stack.

Signup update: the browser verified exactly two form inputs (email and password), minimum password validation, account creation, sign-in, isolated analyst workspace assignment and mobile layout. Open two-field signup is available in demo mode; existing-bank enrollment remains invitation-controlled through the API.

Cloud update: **23 backend tests pass** after adding Neon transaction/replay persistence, request-scoped coordinator execution, and Google's supported full-batch RDP accountant adapter. The frontend production build passes. Live HTTPS bank APIs return 401 without the correct client key and 200 with it. A live three-bank round completed and published model v1. Same-origin secure-cookie login, local bank scoring, cited retrieval, case creation/review notes, graph access, and persistent Neon privacy accounting passed through the public frontend. See `reports/cloud-deployment.json`. Vercel's existing deployment protection settings were preserved; no paid Railway upgrade was made.
