# Operating runbook

Local: initialize secrets with `python -m scripts.dev init`, start coordinator plus three bank processes, then the Vite frontend. The launcher stops its direct service processes when interrupted. Start from the repository root so relative runtime paths resolve consistently.

Docker: set unique `.env` secrets and `POSTGRES_PASSWORD`; run `docker compose up --build`. PostgreSQL has a readiness check; bank endpoints are internal and not exposed to the host. Frontend listens on host loopback port 8080. Coordinator has no access to bank volumes. Dockerfiles are provided for the API, bank client, frontend and native Flower coordinator. They were not built here because Docker was unavailable. Pin image digests and Python lock files as part of a reproducible deployment pipeline; Python requirements currently use bounded ranges.

Institutional deployment requires independent hosts and data ownership, TLS on every bank link (prefer mTLS), DNS allowlists, secret provisioning/rotation, SSO/MFA, a persistent central database, encrypted storage, reviewed cryptographic aggregation, a supported privacy training/security stack, capacity limits and monitoring. Configure `COOKIE_SECURE=true` and the exact HTTPS `FRONTEND_ORIGIN`. Do not run the supplied API with multiple workers: round exclusion and rate limiting are process-local. Introduce a durable job queue, leader election and shared limits first.

Keep the coordinator health endpoint monitored, plus failed rounds, node unavailability, privacy budget rejections, DB errors, authentication failures and the age of approved intelligence. The `/ws/rounds` endpoint supplies authenticated snapshots; the UI uses polling. No Prometheus/Grafana stack is preconfigured. Rotate client keys separately per bank, update that bank's deployment and coordinator environment, then re-enroll. Never put every bank's credential in a bank container. Default Compose does not provide managed secret encryption.

Backups: perform consistent PostgreSQL dumps (or SQLite online backup) of the coordinator; separately back up each bank's local DB, array/model files, privacy ledger and unprotected-release flag under that bank's controls. Encrypt backups, restrict restore permissions and test recovery. Never restore privacy accounting to an older state while retaining releases made after the snapshot. Treat such a restore as requiring privacy/security incident review. Record backup time, ledger sequence, model version and released artifacts. The coordinator must not collect raw bank backups.

Restore order: bring up central DB, check migrations, restore bank-local journals and models consistently, verify client credentials and endpoint health, verify latest model metadata, then enable training. Interrupted coordinator jobs are marked failed on startup instead of silently replaying releases. Failed aggregation may already have consumed bank-local privacy budget.

TLS ingress example: `deployment/tls.conf.example`; replace domain/certificate paths and route WebSockets through the actual ingress. It is a template, not installed TLS. At-rest encryption belongs to the volume/database/KMS layer and is not claimed by the application.
