# Privacy mechanism and boundaries

The implemented training mechanism computes full-batch logistic gradients for each record. Fixed public class weights are positive=1 and negative=0.12. Each complete record gradient, including intercept, is clipped in L2 norm to C. The bank adds independent Gaussian noise with standard deviation sigma*C to the sum, divides by its fixed public synthetic cohort denominator, and performs a gradient step. The optional FedProx term depends only on the current and received model state and is post-processing relative to the clipped/noised gradient.

Opacus `RDPAccountant` composes **every protected gradient step**, sample rate q=1, across previous local releases and the proposed release. There is no claimed sampling amplification. Epsilon is recomputed for the requested delta; changing noise or delta does not erase history. Accounting is per bank. Disjoint synthetic bank populations permit parallel composition as a research assumption; overlapping real people across institutions would require a different analysis.

The intended adjacency is add/remove one record with a fixed, public cohort denominator and fixed preprocessing. Public cohort sizes are 4,500, 3,500 and 2,000. Replacing arbitrary records has sensitivity up to 2C and is **not** the reported accountant configuration. Cohort-size changes, learned preprocessing, private class weights, or private evaluation metrics invalidate these assumptions without further analysis. Never apply the report to arbitrary real datasets.

The local journal is written before the response leaves the node. A completed release consumes privacy even when aggregation fails or a response is lost. A retry of a known round returns the cached release; it does not resample noise. A crash after writing spending but before completing the cached response may overcount on retry; this is conservative. It does not deliberately undercount. Concurrent requests use a SQLite immediate transaction. The local privacy history file is atomically replaced. Protect both local DB and journal from rollback or deletion. No claim is made against a bank administrator rolling back its storage.

An unprotected training request writes an irreversible history flag in that experiment's local store. Later protected requests reject that history. Start a new isolated **synthetic** experiment to compare no-DP and DP settings; do not reset accounting to obtain more releases on private data. Models are risk rankings, not calibrated fraud probabilities. Synthetic holdout metrics and class-imbalance weighting must be interpreted together.

NumPy's pseudorandom generator is seeded from operating-system entropy, but it is not a reviewed cryptographic DP implementation. Opacus supplies the supported accountant; per-record Gaussian clipping is implemented explicitly. This is **not Opacus PrivacyEngine training**, has not had a formal proof or floating-point security review, and does not claim production DP guarantees. See [Opacus accounting](https://opacus.ai/tutorials/intro_to_advanced_features) and [PrivacyEngine secure mode](https://opacus.ai/api/privacy_engine.html).

Aggregation is a **plaintext academic simulation**. Individual updates are visible to the coordinator. No pairwise masking, threshold secret recovery or cryptographic dropout tolerance is implemented. Flower's [SecAggPlusWorkflow](https://flower.ai/docs/framework/ref-api/flwr.server.workflow.SecAggPlusWorkflow.html) is a possible future integration, not an enabled capability. TLS examples protect transport when configured; local demo HTTP does not.

Locality controls do not anonymize model updates. Membership inference, model inversion, model poisoning, private evaluation leakage, duration/participation side channels and a compromised client remain relevant. DP alone does not solve those risks. Hashes stored on model artifacts detect accidental change when checked against trusted metadata; hashes are not signatures or authenticity proof.
